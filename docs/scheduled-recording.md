# 无节目单的独立时段录制

订阅页 → 新建订阅 → 匹配方式选择“独立时段（无需节目单）”。
选择已启用的频道、星期、开始时刻、规则时区和录制时长，点击“预览未来 7 天”确认后保存。
预览只读取数据，不创建订阅或录制任务。

规则时区填写 IANA 名称，例如 `Asia/Shanghai`、`Europe/London`、`America/New_York`。
预览同时显示规则时区和浏览器本地时间。夏令时开始时不存在的当地时刻跳过；
结束时重复的当地时刻仅执行第一次。时长按实际经过秒数计算，支持跨午夜，最长 12 小时。

```json
{
  "name": "晚间新闻",
  "match_type": "channel_schedule",
  "channel_id": "example-channel",
  "time_rule": {
    "weekdays": [0, 1, 2, 3, 4],
    "time": "18:00",
    "timezone": "Europe/London",
    "duration_sec": 3600
  },
  "asr_enabled": true,
  "llm_enabled": true,
  "push_enabled": false
}
```

星期一为 0，星期日为 6。API 可省略 weekdays 表示每天；页面要求明确选择星期。
调度按 `(channel_id, start_time)` 幂等，重复轮询不会重复创建同一开始时刻的采集。
多个订阅命中同一频道同一开始时刻时共享一个任务，新建任务使用这些命中的最长结束窗口。
只有临近任务入队；服务停机后，仍处于有效时段的独立规则可补建剩余窗口，已过去的整档内容不会自动补录。

原“EPG 时刻匹配”的 `channel_time` 行为保持不变：它需要节目单，且容差范围内可能匹配多档节目。
它与独立时段不是同一规则，旧订阅不会自动迁移。

## 窗口与完整性

调度会在临近任务的相关频道上向后查看订阅节目，裁剪尚未开始任务之间重叠的片头/片尾缓冲。
裁剪不会缩短节目本身；取消相邻订阅后，尚未开始任务可重新计算所请求的缓冲。
已经运行的采集不会被调度器强行中断。节目本身重叠，或前一采集仍在运行时，详情页会显示冲突。
录制仍受总并发和同频道并发限制，缓冲裁剪不能保证采集切换完全无间隙。

`schedule_late_seconds` 表示相对计划窗口的迟开始时间；`missing_head_seconds` 表示按节目时间估算的头部缺失。
缩短了预录缓冲不等于丢失节目。重试时若已有封口片段，头部缺失参考已保留的首段起点。
`missed_seconds` 是旧的计划窗口指标，不能当成精确内容缺失。旧录像没有新指标时显示未知，不改写历史媒体。

停用订阅后，已排队任务在实际采集前检查订阅是否启用；全部关联订阅均停用时取消任务，手工录制不受影响。已运行的采集不会被停用操作中断。规则编辑作用于后续新生成任务，已排队任务不自动重排。
