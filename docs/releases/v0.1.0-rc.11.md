# IPTVPilot v0.1.0-rc.11

本版本修复 rc.10 中「换源逻辑从未生效」的问题。

## 问题

rc.10 引入了「同源重试一次，再换备用源」的策略，但集成验证发现**换源从未发生**：任务在第一个源上重试到上限后直接失败。

根因是 `retry_count` 同时承担了两个职责——同一源的重试预算，以及全局重试上限。当它达到 `RECORDING_MAX_RETRIES` 时，处理函数直接进入失败分支，没有机会执行换源判断。

## 修复

- 换源判断只依据 `source_attempts`（当前源已失败次数），`retry_count` 不再参与
- 总尝试次数按 `retry_count + source_switches` 封顶，避免备用源过多时无限循环
- 换源后 `retry_count` 归零，让新源拥有独立的同源重试预算
- `sources_exhausted` 仅在确实没有未尝试的源时标记；换源预算用尽标记 `retry_exhausted`

## 升级

```bash
docker compose pull
docker compose up -d
```

本版本无数据库结构变更。

## 验证

- `ruff check .` 通过；`pytest` 84 passed
- 单元测试覆盖：首次失败保持同源、同源用尽后切换、无源可换时标记耗尽、换源次数封顶
- 建议升级后观察一次真实的换源事件：管理台「录制」页面中，失败的录制详情会显示 `source_switches` 和 `source_switched_reason`
