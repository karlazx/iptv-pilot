# IPTVPilot v0.1.0-rc.5

本版本让录制器支持并发，解决相邻节目重叠时后一条晚开始、甚至只剩几秒的问题。

## 主要变化

- 录制器默认同时处理 2 路任务（`RECORDING_CONCURRENCY=2`，范围 1-8），每路独立 worker。
- 同一频道最多同时录制 2 路（`RECORDING_MAX_PER_CHANNEL=2`）；超过上限保持排队，窗口关闭前仍无槽位则标记 `overlap_wait_timeout`。
- 认领任务使用 `claim_id` fencing 和心跳租约：worker 崩溃或容器重启后，任务可被其他 worker 接管，旧 worker 的完成/失败更新不会覆盖新结果。
- 过期窗口（默认节目结束 5 分钟后）不再启动补录，避免产生 1 秒录像。
- 定时任务按 `(channel_id, start_time)` 去重，同一节目被多个订阅命中时只录一份。
- `/api/system/status` 新增 `recordings_running`、`recordings_queued`、`recording_workers`；录像页每 10 秒刷新并显示当前录制数。
- 新增 `scripts/migrations/migrate_recorder_concurrency.py`：删除旧的唯一去重索引、补建并发索引，可选合并历史重复任务、清理崩溃遗留的 `.part.ts`。
- `recorder` 容器增加 `mem_limit: 2g`。

## 升级

```bash
docker compose pull
docker compose up -d
docker compose run --rm --no-deps recorder python -m scripts.migrations.migrate_recorder_concurrency --dry-run
docker compose run --rm --no-deps recorder python -m scripts.migrations.migrate_recorder_concurrency --apply --merge
```

多源管理（rc.4）的迁移脚本仍需先执行一次；rc.5 不改变源数据。

## 已知限制

- 多容器横向扩容仍需共享同一份录像目录，并依赖 MongoDB 租约；默认只部署单容器。
- 重叠节目仍分别保存为独立文件，不会自动拼接。
- 默认仍是可信内网部署，不要直接暴露管理台、iptv-api、MongoDB 或 MongoDB Search。
