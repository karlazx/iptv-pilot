# IPTVPilot v0.1.0-rc.7

本版本整理仓库结构、限制容器内存，并修正转码时长校验。

## 主要变化

- **仓库结构整理**：根目录只保留构建入口、README、LICENSE、CHANGELOG 和配置样例；社区文档移入 `.github/`，路线图与第三方声明移入 `docs/`；`requirements-*.txt` 合并为 `requirements/`；`scripts/` 按 `db` / `migrations` / `channels` / `setup` / `diagnostics` / `smoke` 分组，并新增 `scripts/README.md`。Compose 与文档同步改用模块入口。
- **删除无用文件**：`uv.lock`（无构建或 CI 引用）、`scripts/configure_push_from_stdin.py`（推送配置已可在管理台修改）、`scripts/diagnose_coze_api.py`（Coze 非默认渠道）。`SUPPORT.md` 并入 `.github/CONTRIBUTING.md`。
- **容器内存上限**：为全部常驻服务设置 `mem_limit`。此前 `iptv-api`、`channel-sync`、`stream-quality`、`epg-engine`、`scheduler`、`llm`、`push`、`web` 没有上限。
- **修复 `stream-quality` 启动路径**：目录整理后该服务仍调用旧模块名，升级后会反复重启。
- **放宽转码时长校验**：默认阈值改为 0.95（`RECORDING_ENCODE_MIN_DURATION_RATIO`），避免重编码尾帧裁剪被误判为失败。
- 部署文档新增「主机内存与 earlyoom」一节，记录早期 OOM 杀进程后的恢复步骤。

## 升级

```bash
docker compose pull
docker compose up -d
```

升级后确认 `stream-quality` 为 `Up` 且不再重启：

```bash
docker compose ps stream-quality
docker compose logs --tail 20 stream-quality
```

若 `.env` 中仍有 `IPTV_PILOT_WEB_IMAGE` / `IPTV_PILOT_WEB_TAG` / `IPTV_PILOT_WEB_PULL_POLICY`，可以删除。旧版 Compose 中的脚本路径（`scripts/seed_channels.py` 等）需要改为新版模块入口，或直接用本版本的 `docker-compose.yml`。
