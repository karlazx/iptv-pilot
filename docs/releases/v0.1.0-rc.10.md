# IPTVPilot v0.1.0-rc.10

本版本改进录制失败后的重试策略，减少一次上游抖动导致整段录像失败的情况。

## 主要变化

- **窗口检查**：重试前检查剩余时长。不足原始窗口 20%（`RECORDING_RETRY_MIN_FRACTION`）时不再重试，标记 `insufficient_window`，避免录制节目末尾的几秒钟又失败一次。
- **同源优先，再换源**：第一次重试保持原 URL，避免不同源之间的重复或时差；仍失败才按优先级切换到未尝试过的备用源。
- **换源上限**：`RECORDING_MAX_SOURCE_SWITCHES`（默认 2）限制单个任务最多换几次源，所有源都失败时标记 `sources_exhausted`。
- **差异化退避**：上游类错误（502/503/504、连接拒绝）等待 120 秒，短片段类错误等待 30 秒。
- **诊断字段**：`retry_window_remaining`、`source_attempts`、`source_switches`、`source_switched_at`、`source_switched_reason`。

## 新增配置

```dotenv
RECORDING_RETRY_MIN_FRACTION=0.2
RECORDING_RETRY_DELAY_SECONDS=30
RECORDING_RETRY_UPSTREAM_DELAY_SECONDS=120
RECORDING_SOURCE_RETRIES=1
RECORDING_MAX_SOURCE_SWITCHES=2
RECORDING_RETRY_SWITCH_DELAY_SECONDS=15
```

三者均为可选，不配置时使用上面的默认值。

## 升级

```bash
docker compose pull
docker compose up -d
```

本版本无数据库结构变更，不需要执行迁移脚本。

## 说明

重试策略只决定「失败之后怎么办」，不会提升上游源的稳定性。若某个频道的首选源持续抖动，建议在管理台查看该源的质量数据，必要时调整优先级或替换首选源。
