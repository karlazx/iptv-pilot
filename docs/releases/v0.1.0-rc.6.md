# IPTVPilot v0.1.0-rc.6

本版本重整了直播源与频道的关系、把推送和录制压缩做成可配置项，并移除多余的 Web 镜像变体。

## 主要变化

- **直播源两级结构**：直播源管理按「总源 → 频道 → 线路」展示，总源按官方组播 / IPTV-API 同步 / 第三方 M3U / 用户自定义 / M3U 导入分组，同屏显示每个频道各线路的首选、回退与锁定状态。
- **添加频道支持多线路**：新增频道时可一次填写多条线路，并选择哪一条作为首选；其余自动作为备用。频道详情抽屉可直接新增、删除线路或设为首选，不必再跳转到直播源页面。
- **推送配置进入通用设置**：可选择推送渠道（当前支持邮箱 / 关闭）、收件人、SMTP 主机、端口、账号、密码、发件人与加密方式，保存后推送服务即时生效，并可一键发送测试邮件。密码只显示“已保存”，接口不回显明文。
- **通用设置布局重排**：改为左右两栏，左侧是可修改的配置（缓冲、推送、压缩），右侧是推送事件、规范化池、服务状态和 API 令牌；推送事件列表固定高度、内部滚动，不再被同一行的缓冲卡片拉长。
- **录制压缩**：录制仍以原画质 `-c copy` 保存 TS，新增的 `encoder` 服务在 ASR/摘要完成后把它转成 720p / H.264 / AAC 的 MP4（CRF 26，可调），校验时长通过后替换 `file_path` 并删除原 TS。实测 1080p → 720p 约 6 倍实时，体积约为原来的 15%。可在「通用设置 → 录制压缩」调整分辨率、CRF、编码速度和是否保留原文件。
- **镜像简化**：移除独立的 `-web` 镜像变体，Web 服务复用基础镜像（其中已包含 imageio-ffmpeg），每次发版少构建、少发布一个镜像。

## 升级

```bash
docker compose pull
docker compose up -d
docker compose run --rm --no-deps recorder python -m scripts.migrate_rc6 --apply
```

历史录像会在编码器首次启动时排队压缩（`RECORDING_ENCODE_BACKLOG=true`），不需要手动触发。若希望先观察，可设置 `RECORDING_ENCODE_BACKLOG=false` 或把压缩开关设为关闭。

升级后如仍保留 `IPTV_PILOT_WEB_IMAGE` / `IPTV_PILOT_WEB_TAG` / `IPTV_PILOT_WEB_PULL_POLICY`，可以删除；Web 服务已改用基础镜像。

## 已知限制

- 推送渠道目前只支持邮箱；Coze 适配器保留在代码中但不通过界面配置。
- 转码固定重编码为 H.264 + AAC，不保留多音轨/字幕轨。
- 转码在有 ASR 的录像完成摘要后才进行，以避免与转写争用文件。
- 默认仍是可信内网部署，不要直接暴露管理台、iptv-api、MongoDB 或 MongoDB Search。
