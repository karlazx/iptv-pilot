# IPTVPilot v0.1.0-rc.12

修复后台转码队列停滞导致新录像首次播放等待时间较长的问题。

录制完成时会将 `next_encode_attempt_at` 写为 `null`，表示无需等待。
此前转码器仅匹配字段缺失或重试时间已到的任务，遗漏了显式空值，导致任务一直停留在 `pending`。
未转码的 TS 录像首次播放时，需要先完成整段 MP4 转封装才能返回视频。

本版本让空值与字段缺失均可立即领取，并优先处理近期完成的录像。
未来的重试时间仍然受到限制；ASR/摘要终态检查、原子领取和租约保护保持生效。

## 升级

将镜像版本更新为 `0.1.0-rc.12`（AI 变体使用 `0.1.0-rc.12-ai`），然后执行：

```bash
docker compose pull
docker compose up -d
```

无需数据库迁移。转码器会按配置的并发数自动处理已有积压。
积压消化前，尚未转码且没有播放缓存的录像，首次播放仍需等待转封装。

## 验证

增加真实 MongoDB 集成测试，覆盖字段缺失、显式空值、已到及未来重试时间、
近期录像优先、活跃任务互斥、ASR 期间不可领取和过期租约接管。
本地运行这些测试时，需通过 `TEST_MONGODB_URI` 指向独立测试实例；CI 自动提供该实例。
