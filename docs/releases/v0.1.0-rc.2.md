# IPTVPilot v0.1.0-rc.2

这是 `v0.1.0-rc.1` 之后的候选版本，重点修复录制早退、MPEG-TS 解析崩溃，以及可选 AI/播放镜像的依赖隔离问题。

## 主要变化

- 录制完成后校验实际媒体时长；显著短于请求窗口时判失败并按剩余时间重试，避免把上游提前断流的几秒片段当成完整录像。
- 录制 ffmpeg 增加 HTTP 自动重连参数，桥接或上游短暂断流后可继续录制。
- 修复 Debian 12 上静态 ffmpeg 解析 MPEG-TS SDT 时的 gconv/iconv 崩溃（`GCONV_PATH`），录制不再随机 `SIGSEGV`。
- 新增 `-ai` 镜像变体，ASR/recorder 使用独立 AI 镜像；该镜像包含 faster-whisper 和 PyAV，并固定 `av==18.1.0`。
- Web 镜像启用 imageio-ffmpeg，支持在浏览器内播放 TS 录像。
- 镜像 tag 和 pull policy 可通过 `IPTV_PILOT_AI_*` / `IPTV_PILOT_WEB_*` 配置，本地构建与 GHCR 版本化升级互不干扰。
- 增加录制早退检测单元测试。

## 升级

使用 GHCR 版本化镜像时，在 `.env` 中设置：

```dotenv
IPTV_PILOT_IMAGE=ghcr.io/karlazx/iptv-pilot
APP_TAG=0.1.0-rc.2

IPTV_PILOT_AI_IMAGE=ghcr.io/karlazx/iptv-pilot
IPTV_PILOT_AI_TAG=0.1.0-rc.2-ai
IPTV_PILOT_AI_PULL_POLICY=missing

IPTV_PILOT_WEB_IMAGE=ghcr.io/karlazx/iptv-pilot
IPTV_PILOT_WEB_TAG=0.1.0-rc.2-web
IPTV_PILOT_WEB_PULL_POLICY=missing
```

然后执行：

```bash
docker compose pull
docker compose up -d
docker compose ps
```

仍使用本地构建时，把 `IPTV_PILOT_AI_IMAGE` / `IPTV_PILOT_WEB_IMAGE` 保持为本地镜像名，tag 改为 `0.1.0-rc.2`，pull policy 保持 `never`，并执行 `docker compose build asr recorder web`。

## 已知限制

- 默认仍是可信内网部署，不要直接暴露管理台、iptv-api、MongoDB 或 MongoDB Search。
- 真实转写、摘要和向量搜索需要自行配置模型缓存或服务凭据；默认配置仍使用 mock 后端。
- 录制器当前按单条任务顺序处理；多条录像时间重叠时，后一条可能晚开始。
- 项目不提供任何可工作的频道、IPTV 订阅或第三方 EPG 地址。
