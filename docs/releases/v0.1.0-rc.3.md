# IPTVPilot v0.1.0-rc.3

这是 `v0.1.0-rc.2` 的修正版本：移除录制 ffmpeg 的无上限自动重连，避免上游彻底断流时 ffmpeg 一直重连到录制窗口结束后才因超时失败。

## 主要变化

- 录制 ffmpeg 使用 15 秒读超时（`-rw_timeout`），不再配置无上限的 `-reconnect`。
- 上游中断时 ffmpeg 会及时退出，再由实际时长校验判断是否为早退，并按剩余窗口重试。
- PyAV 录制回退同步移除自动重连，仅保留读超时。
- 保留 rc.2 的早退检测、AI/Web 镜像隔离、`-ai` 镜像和可配置 pull policy。

## 升级

使用 GHCR 版本化镜像时，在 `.env` 中设置：

```dotenv
IPTV_PILOT_IMAGE=ghcr.io/karlazx/iptv-pilot
APP_TAG=0.1.0-rc.3

IPTV_PILOT_AI_IMAGE=ghcr.io/karlazx/iptv-pilot
IPTV_PILOT_AI_TAG=0.1.0-rc.3-ai
IPTV_PILOT_AI_PULL_POLICY=missing

IPTV_PILOT_WEB_IMAGE=ghcr.io/karlazx/iptv-pilot
IPTV_PILOT_WEB_TAG=0.1.0-rc.3-web
IPTV_PILOT_WEB_PULL_POLICY=missing
```

然后执行：

```bash
docker compose pull
docker compose up -d
docker compose ps
```

## 已知限制

- 录制器仍按单条任务顺序处理；多条录像时间重叠时，后一条可能晚开始。
- 默认仍是可信内网部署，不要直接暴露管理台、iptv-api、MongoDB 或 MongoDB Search。
- 真实转写、摘要和向量搜索需要自行配置模型缓存或服务凭据。
- 项目不提供任何可工作的频道、IPTV 订阅或第三方 EPG 地址。
