# IPTVPilot v0.1.0-rc.8

本版本修复频道检测的内存缺陷，该缺陷可导致宿主内存耗尽。

## 主要变化

- **频道检测增加下载限制**：`scripts/channels/diagnose_live_quality.py` 此前用 `client.get()` 全量读取源，再当作播放列表解析。若某个导入的源实际指向视频文件，整个文件会被读进内存。
  - 播放列表改为流式读取，上限 2 MiB
  - `Content-Type` 为 `video/*` 或 `audio/*` 时直接拒绝
  - 响应不是 HLS（不以 `#` 开头）时拒绝
  - 分片下载改为流式，上限 64 MiB
- **可读的错误信息**：检测失败会显示具体原因（如 `not a playlist: content-type video/mp4`），不再是异常类名。
- 新增故障复盘文档 `docs/incidents/2026-11-06-docker-memory-pressure.md`。

## 实测效果

用 11-06 导入到「广东卫视」的 1.85 GB MP4 验证：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 1.85 GB MP4 | 1 GB 容器被 OOM 杀死 | 0.2 秒拒绝，峰值内存 4.1 MB |
| 正常 HLS 源 | 正常 | 正常（8.21 / 8.03 Mbps） |

## 升级

```bash
docker compose pull
docker compose up -d
```

建议同时确认 `stream-quality` 容器已使用新镜像：

```bash
docker compose ps stream-quality
docker compose logs --tail 20 stream-quality
```

## 仍建议处理（本版本未包含）

- 宿主 `containerd.service` 的 `OOMScoreAdjust=999`（官方默认为 `-999`）。这是本次故障中容器运行时被优先杀死、进而所有容器失联的直接原因，属于宿主级配置，需要单独评估。
- 组播桥接 `/ts/` 路径不经过并发限制。它仅由录制器使用，而录制器已有 `RECORDING_CONCURRENCY` 上限，因此风险可控。
